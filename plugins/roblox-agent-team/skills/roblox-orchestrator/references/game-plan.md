# Game plan (new games only)

Write it to `design/game-plan.md` in the working folder before any code.
Every section is either **answered** or **declined with a reason**. Declining
a third of these is normal for a first version. Leaving one blank isn't.

```
## 1. Overview        name, genre, platform, target age, devices
## 2. Pitch           one sentence + why play this over the game it resembles
## 3. Core loop       what the player does at minute 0, 5, 30, and tomorrow
## 4. Feel            what it should feel like; when the first win lands
## 5. Market          2-3 real comparable games, what they do well and badly
## 6. Mechanics       movement, combat, economy, world: the feature list
## 7. Progression     short, medium, long-term goals
## 8. Content         maps, enemies, items, collectibles
## 9. UI              every screen; clicks for the most common action
## 10. First 5 min    the tutorial, beat by beat
## 11. Art + audio    style every asset must match; music/SFX roles
## 12. Architecture   services used, our own systems, server vs client split
## 13. Saving         what persists, what happens when a save fails
## 14. Security       what the server validates; what an exploiter would try
## 15. Multiplayer    players per server; what happens when one leaves
## 16. Monetization   passes/products, or declined
## 17. Out of scope   what this version will NOT do
```

Example of a decline: `## 16. Monetization: declined, prototype only, no
Robux until the loop is fun.`
